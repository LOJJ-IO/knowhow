**Bug: the grid-guidelines addition briefly broke the whole homepage — real hydration crash, not user error** (2026-09-04). Right after the `GuidelinesOverlay` feature above landed, the user reported "I don't even see the logo anymore." Root-caused via `.next/dev/logs/next-development.log` rather than guesswork: an `Uncaught Error: Hydration failed` logged at the exact timestamp of that change, pointing at `GuidelinesOverlay` inside `LandingHero`. Mechanism: `editMode` in `landing-hero.tsx` is read from `localStorage` via a lazy `useState` initializer, so its value is `false` on every server render but can already be `true` on the client's *first* render (during hydration) if the user had left edit mode on in a prior session — a real, easy-to-hit case here since edit mode was actively in use for the drag work above. `GuidelinesOverlay`'s entire subtree (grid + control panel) mounted/unmounted based on that diverging value, which is a *structural* mismatch React cannot patch quietly (unlike attribute-only mismatches, which `suppressHydrationWarning` on `Draggable`'s own div already handled safely) — React tore down and rebuilt the surrounding tree, and evidently didn't recover cleanly for the user. A second, milder instance of the same bug class was found in the same file: the pre-existing "Copy config" button's presence and the "Edit positions"/"Done editing" label both also branch on raw `editMode`.

Fix: added `src/lib/use-hydrated.ts` — a `useHydrated()` hook built on `useSyncExternalStore` (`getServerSnapshot` returns `false`, `getSnapshot` returns `true`), which is React's built-in mechanism for values that legitimately differ between server and client; it re-renders after hydration without emitting a mismatch, and — a real lint constraint this repo enforces, see the lazy-`useState`-for-localStorage lesson above — a first attempt using `useEffect(() => setMounted(true), [])` was hard-rejected by the project's React-compiler lint rule ("Calling setState synchronously within an effect can trigger cascading renders"), which was the actual reason `useSyncExternalStore` was reached for here instead of the more common effect-based "mounted" pattern. Both `GuidelinesOverlay`'s `visible` gate and `LandingHero`'s two `editMode`-branching spots (`Copy config` button, edit-mode button label) now AND against `mounted`, so the first client render always matches the server (`false`) and only reflects the real localStorage-backed value after hydration completes. Verified by scripting the exact failure precondition in Playwright — enable edit mode (persisting `draggable:editMode=1`), then hard-reload — and confirming zero console/page errors post-fix (previously reproduced the logged hydration error on demand pre-fix), with the logo and mark both still rendering.

Lesson: when self-hosting a specific weight from an API that encodes italic as an offset weight number, query that exact weight alone rather than a broader multi-weight request, to avoid silently picking up the wrong style variant.
